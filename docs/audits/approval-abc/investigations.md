# R5 / R6 / R9 — Investigation only

Scope approved 29 October 2026 (Asia/Bangkok). These proposals are not implemented. No migrations, production writes, permission changes, feature removals or deployment are authorized by this document.

## R5: Observability design

**Observed:** `src/lib/http.ts` logs an unexpected exception's name. `src/lib/connected/observability.ts` measures assets.list, project.hub, search and connections.list through their route wrappers. It stores minute histograms for seven days; operations reports aggregate fifteen minutes. Vercel runtime logs and grouped errors returned403 in the audit. The public health response establishes readiness, not absence of runtime errors.

**Proposed contract:** generate a server request UUID at the API boundary; include it as `X-Request-ID` in responses and in the generic failure message metadata. Never accept an inbound ID as authoritative. Log structured JSON with requestId, route template (not raw URL), method, status, stable error code, durationMs and server-side sanitized exception type/stack. Preserve existing user-facing errors and response fields; any additional requestId is additive. Do not collect request bodies, cookies, Authorization headers, OAuth tokens, search terms, document bytes, filenames, email addresses or full SQL parameters. Exception messages/stacks require a redaction function with secret/URL/query scrubbing and length bounds; raw database messages must not be logged.

**Metrics:** extend the existing wrapper to costs and project-template operations, document transfers/finalization and imports. Distinguish server failure from expected validation/conflict/permission errors; report histogram bounds rather than fabricated exact percentiles. Keep metric failures best-effort; the metrics write must not change transaction success. Measure wrapper overhead before rollout.

**Access and retention:** request least-privilege read access to the known Vercel team/project; do not create bypass links or change roles automatically. Determine actual plan/retention/cost before selecting platform or paid drain features. If platform access stays blocked, application-level redacted counters remain available but do not replace stack traces or certify error-free production.

**Acceptance:** injected unexpected failure produces one correlated, redacted log; API and UI can quote its ID; expected409 is not counted as500; logging failure cannot fail the business operation; secret canaries never appear in output. Roll out the wrapper to a small route set first, compare latency/error metrics, and retain the prior logging path as a code rollback. No new vendor is required by default.

## R6: Structured province design

**Observed:** region classification is exact-alias based in `src/lib/board-room/regions.ts` and SQL generated from the same registry. Five ISO codes are ID-KB, ID-KT, ID-KS, ID-KI, ID-KU. Free-text location is preserved; missing/unrecognized are explicit. Regional aggregation counts DISTINCT project IDs. Project and asset figures are independent.

**Proposed contract:** introduce optional `provinceCode` using the five-code registry for projects and assets independently; retain `location` verbatim as descriptive text. Explicit provinceCode is authoritative when set. Omitted provinceCode preserves its current value during edits/import merges. Explicit null clears the structured value and opts into legacy text classification; show this effect in preview. Conflicting text is a data-quality warning, never grounds to overwrite either input. Asset province must never silently set project province or vice versa.

**Compatibility:** old clients/files omit the new field and continue to work. Add a Province code CSV column and field mapping; stable project identity remains Project ID and asset identity remains RUPTL Code. Include province in export, saved-view/filter contracts, reports, asset queries and both map predicates. The two map surfaces must consume the same effective-region expression. No automatic geocoding or coordinate invention.

**Migration proposal:** additive schema/JSON contract with indexes appropriate to measured queries. First run a read-only dry-run that classifies exact aliases, missing, ambiguous/unrecognized and explicit-code/text conflicts. Preview affected IDs, old text, proposed code and reason; never infer a province from a city or substring. Confirmation requires authorized admin, preview hash, record-version checks, idempotent receipt and atomic writes. Apply only exact aliases selected in preview; preserve text and all unrelated fields/history. No production data dry-run has been performed in this task.

**Acceptance:** all five province totals + missing + unrecognized equal distinct matching projects across categories, pagination and exports; structured codes and legacy aliases agree; ambiguous text remains visible; project/asset relationships cannot duplicate counts. Exercise new/old clients, CSV blanks/explicit clears and concurrent changes. Rehearse a rollback that leaves additive data intact; rollback of application code must preserve the new metadata (a retention guard may be needed). Never roll back populated data by overwriting newer work with a snapshot.
