# Task ranges, dashboard, label editing and Expense retirement

21 October 2026 (Asia/Bangkok). The owner approved this bounded design after specifying start/end dates per task. Implementation is a review candidate; production release requires approval of its concrete preview and migration 0016. Previous production is ab65d79 with schema 0001–0015.

Task.startDate is optional; existing dueDate remains the deadline/end date. A start requires an end on or after it. Due-only tasks and legacy command fingerprints remain compatible. Migration0016 adds a nullable column and range constraint without backfilling or deleting rows. Create/edit/bulk/import/templates, drafts, duplication, recurring tasks and Google event bodies carry the range. Recurrence preserves duration; all-day Calendar events end exclusively the day after the task's inclusive end. Timed multiday events begin at the first valid local minute on the start day and end at the due time; Google reminders refer to the event start. Existing due-only timed events retain their 30-minute duration.

List/board show a compact range; Calendar displays work on every inclusive scheduled date, including tasks ending beyond its current query window. Legacy from/to API filters still mean deadlines; explicit dateMode=overlap uses interval overlap. Schedule drilldowns and saved views preserve that mode and expose a clearable date-window caption. Calendar navigation retains selected-day state.

Overview places the interactive map before metrics and charts. Created/completed is replaced by 14 scheduled-work days, based on full database aggregates and account calendar dates. A task spanning several days is counted on each scheduled day. Attention bars show overdue/unassigned/unscheduled open tasks; these groups can overlap and are labelled nonexclusive. Existing status, priority, deadline, workload and project progress remain. Dependency creation is already disabled in the application, so attention uses supported task data. Historical trend report fields remain compatible for existing consumers.

Project labels can be edited by the sole administrator in Overview and Connection. Inline chip rename normalizes and validates labels while preserving other chips/search drafts. Tasks continue to inherit project labels. Successful saves follow the renamed map; conflicts preserve the draft and require explicit reload. Initial load failures cannot overwrite labels. Suggestions now occupy bounded inline space: the previous floating panel covered mobile Save. It keeps its height while focus moves within the form so pointer clicks remain stable. Long project names/references/owner text wrap inside cards; descriptions use an intentional summary while detail pages retain the full text. A separate probe also reproduced project-detail overflow from unbroken descriptions; the header now allows its text column to shrink and wraps long words. The strengthened five-viewport detail checks and15 existing project-identity cases passed together (20 cases).

Expense controls, ledger fetches and recording flows are retired. Authenticated legacy ledger/write requests return 410; unauthenticated requests still fail authentication. Historical tables/records, money precision and project-deletion cascade remain. Tests seed historical records directly into disposable databases rather than re-enabling the retired public feature. Cost groups and per-option/unit totals are unchanged.

## Evidence and release boundary

Baseline public audit covered 60 page/viewport states. It found no page-wide overflow; a separate long-text probe reproduced internal card clipping at 320/390/768/1440. Browser regressions reproduced missing Overview editing, Expense controls, the old six-chart dashboard and missing task-date fields on the prior compiled application. Initial new browser testing exposed the mobile suggestion/Save collision; the corrected label/picker/layout suite passed 12 cases. A heading assertion was corrected to inspect the complete project name within the heading, which also contains an avatar and task count.

Local unit/PostgreSQL suite passed 179 tests. Date integration checks cover persisted ranges, merged updates, atomic batch rollback, SQL range constraints, recurrence duration, all 14 aggregate/drilldown matches and retained historical Expense data. Initial feature suite passed 17 cases; the 12-case corrected suite covers all its label/layout failures plus existing picker behavior. Exact-source CI, deployed-preview evidence and final counts are recorded in the PR after completion. The CI job budget increases 15→20 minutes for the expanded suite; individual test limits and zero retries are unchanged.

No owner account/org data is impersonated. Tests use disposable PostgreSQL/synthetic sessions or isolated browser demo data. Physical devices/other browsers, screen-reader acceptance, fresh Google consent/Calendar delivery, field/load and backup recovery are outside the observed synthetic evidence.

For an approved rollout, retain previous migration hashes, run only additive 0016, verify the exact immutable source/digest and schema health before promoting, then restore automatic domain assignment. Recovery must preserve start/end dates, interval-filter semantics, retired Expense behavior, exact Cost units/amounts, private-file guards and Calendar deletion recovery; prefer a compatible fix forward. No historical Expense deletion or migration backfill is authorized.
