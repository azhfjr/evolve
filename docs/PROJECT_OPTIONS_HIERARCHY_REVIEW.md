## Implemented behavior

Project settings offer Pembangkit, Transmisi and Gardu Induk. Optional Planned COD follows Description, with Not set and years 2026–2040. No year is assigned to old projects. Option names and count are managed immediately after that metadata; the Cost section follows those same groups. Renaming an option preserves its item identifiers and values. Existing projects stay Uncategorized; portfolio search and category filters include the new value. Project labels can be selected from the paginated global catalog without typing, searched or created. Keyboard navigation, loading, retry and stale-response handling are included. Pending label text is merged on Save; closing suggestions cannot shift a Save button between pointerdown and click.

Connection shows one selected hashtag root, each matching/contextual Project below it, then each Project's own Task nodes. Synthetic label nodes do not enter API DTOs, result counts, navigation or label editing. Task-only/search/page results retain contextual parents. Fit, node/background dragging, wheel/pinch zoom, native/fallback fullscreen and focus restoration remain available. Layout is deterministic, with no idle simulation.

Project costs use up to ten named groups and fifty items across the project. Every item has a title, unit and amount. Supported units are IDR, USD, cUSD/kWh and Rp/kWh. All groups contribute; there is no selected alternative scenario. Amounts use English separators. Money retains two decimals, rates up to six; arithmetic uses integer minor units. Totals, subtotals and finance readback separate every unit. Rates never enter monetary budgets, expense currency selection, recorded expenses or Remaining. Removing a group stages the removal until Save and asks for confirmation if it contains costs.

The Projects overview retains Cards and adds Checklist. Each project exposes expandable Options and Cost items, with exact option/project totals separated by unit. Shared search, status and category filters work across both views; search includes option/cost names and COD. Checklist is a display of cost detail, not stored work-completion checkboxes.

Manage costs opens a focused Cost form; Project settings retain all project metadata. Tabs edit groups without hiding validation failures: an invalid inactive group is activated and its first invalid field receives focus. Desktop uses compact aligned fields, and narrow phones stack unit/amount fields so formatted values remain readable. Headers/actions stay within the viewport, including short landscape screens. New-project drafts retain incomplete grouped fields. Legacy draft rows become General costs; stale hidden cost rows cannot block their completion. An unchanged legacy request whose response was lost reuses its original payload/receipt identity, preventing duplicate project creation. This includes older grouped drafts carrying monetary compatibility rows and no COD field.

## Storage, compatibility and recovery

Migration 0012 adds nullable category and JSON cost_options columns with bounded structural, unit, amount and aggregate checks. Migration 0013 aligns title whitespace/codepoint validation and avoids locale-dependent SQL lowercase rejecting API-valid Unicode pairs. The supported API enforces full Unicode case-insensitive group uniqueness; SQL additionally rejects exact/ASCII-folded duplicates. Migration 0014 adds nullable planned_cod_year with an integer-year range constraint. Omitted updates preserve it; explicit null clears it. None of these migrations backfills, deletes or rewrites existing project data. The eleven released migration files remain unchanged.

Read-time legacy costs appear in General costs. All monetary items from all groups project into the existing cost_items/budget compatibility fields. Labels-only commands and older updates that omit new fields preserve them. A stale older cost editor cannot erase the grouping through a changed compatibility projection. Server/demo guards match. Existing administrator-only access, versions, command receipts, private draft files/tombstones and durable Calendar deletion recovery remain required.

Run the checked migration runner inside the secure Production environment before serving this app; the health route checks category, cost_options and planned_cod_year. Retain a verified backup and the previous deployment while holding automatic alias assignment during preflight. After grouped costs are saved, rolling back to an app without the options-aware compatibility guard can make views or subsequent monetary edits inconsistent. Prefer fixing forward; a recovery deployment must preserve the new guard/projection plus Calendar/private-file safeguards. Additive columns alone do not make an old writer safe.
