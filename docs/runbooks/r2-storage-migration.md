# Migrasi penyimpanan Evolve ke Cloudflare R2

Evolve tetap berjalan di Vercel dan PostgreSQL. Lampiran mempertahankan ID, URL privat, metadata dokumen, dan riwayat versi. Batas unggah dokumen tetap 25 MiB. Setelah R2 menjadi tujuan unggahan, Board Room, Locker Room, dan aset bersama memakai batas gabungan 9.000.000.000 byte. Reservasi aktif, revisi lama, dan penghapusan yang belum selesai tetap dihitung.

## Siapkan akun dan preview

1. Aktifkan langganan R2 pada akun Cloudflare organisasi. Buat bucket Standard privat untuk produksi dan bucket bernama `evolve-r2-test` atau `evolve-r2-test-<suffix>` untuk pengujian. Pastikan akses publik dan domain publik dinonaktifkan.
2. Untuk tiap lingkungan, simpan token Object Read & Write yang hanya mengakses satu bucket di secret manager. Konfigurasikan `R2_ACCOUNT_ID`, `R2_BUCKET`, `R2_ACCESS_KEY_ID`, dan `R2_SECRET_ACCESS_KEY`. Simpan `BLOB_READ_WRITE_TOKEN` selama transisi. Siapkan origin CORS yang tepat sebelum build karena CSP menggunakan endpoint akun R2. Izinkan PUT dan header Content-Type serta If-None-Match. Pada bucket uji saja, tambahkan origin `http://127.0.0.1:3197` untuk probe Chromium dan Firefox.
3. Pastikan preview memakai database, bucket, dan kredensial terpisah. Terapkan migration `0042_attachment_r2.sql` melalui `npm run db:migrate` pada target yang telah diperiksa. Rehearsal pemulihan wajib mencakup cadangan PostgreSQL dan byte dokumen privat. Skrip cadangan release yang lama kini membaca kedua penyedia dan masih dibatasi 100 MiB. Bila data lebih besar, ambil snapshot PostgreSQL dan ekspor objek terenkripsi secara streaming dengan manifest SHA-256. Uji pemulihan sebelum menghapus salinan sumber.
4. Jalankan `npx tsx scripts/r2-probe.ts chromium` dan `npx tsx scripts/r2-probe.ts firefox` dengan kredensial bucket uji. Probe memakai satu objek unik, membuktikan browser mengirim ukuran yang ditandatangani, menolak ukuran dan MIME berbeda, menolak penimpaan, serta memverifikasi akses privat, byte, dan penghapusan. Berhenti jika gate gagal. Konfigurasi CORS dapat memengaruhi hasil. Jangan menggunakan bucket produksi.
5. Dengan `EVOLVE_STORAGE_WRITE_MODE=r2` di preview, uji unggahan di kedua aplikasi, dokumen revisi dan arsip, unduhan privat serta ZIP, pembatalan, dan penghapusan. Uji perubahan bukti dan izin anggota/admin. Bagikan preview yang berhasil sebelum promosi produksi.

## Rilis, salin, dan rekonsiliasi

- Terapkan skema aditif pada produksi setelah cadangan diperiksa. Rilis pembaca kedua penyedia dengan `EVOLVE_STORAGE_WRITE_MODE=blob` dan batas lama. Periksa health, pembacaan lampiran lama, logout, dan penolakan akun tanpa akses. Versi ini menjadi target rollback sebelum ada unggahan R2.
- Jalankan perintah operator dari lingkungan yang memasok secret secara aman. `EVOLVE_R2_EXPECTED_DATABASE` berisi host dan nama database dalam bentuk `host[:port]/database`. `EVOLVE_R2_EXPECTED_BUCKET` berisi `https://<account-id>.r2.cloudflarestorage.com/<bucket>`. Set `EVOLVE_R2_OPERATOR_APPROVED=1` hanya untuk target yang identitasnya sudah diperiksa. URL database dan token tidak dimasukkan ke argumen atau log.
- Jalankan `npx tsx scripts/r2-migrate.ts status`, `backfill`, lalu `reconcile`. Backfill menandai baris lama yang belum ditandai sebagai Blob. Jangan menjalankannya terhadap database yang file lamanya tersimpan lokal. Untuk mengaktifkan R2, lebih dulu pastikan hasil rekonsiliasi untuk bucket produksi baru lulus. Promosikan build kompatibel dengan `EVOLVE_STORAGE_WRITE_MODE=r2` dan `EVOLVE_STORAGE_EXPANDED_QUOTA=1`. Reservasi lama menyelesaikan proses pada penyedia asal. Penanda yang baru dibuat berlaku untuk rujukan dan cleanup.
- Jalankan `npx tsx scripts/r2-migrate.ts copy 10` per batch dan periksa hasil tiap batch. Ulangi backfill untuk sisa baris warisan bila ada. Objek siap diverifikasi ukuran dan SHA-256 sebelum rujukan diperbarui. Baris yang gagal tetap menunjuk ke Blob. Selesaikan kegagalan dan ulangi sampai status tidak menunjukkan file siap di luar R2. Biarkan unggahan lama berakhir atau dibersihkan, lalu jalankan `reconcile` lagi. Cocokkan jumlah serta total byte per penyedia dan status. Uji tautan arsip dan unduhan privat tanpa membuat file sintetis di produksi.
- Cron maintenance menjalankan rekonsiliasi setiap hari. Laporan hilang, terlalu lama, gagal, melebihi 9 GB, atau menunjukkan objek yang tidak cocok membuat R2 menolak reservasi dan izin unggah baru. Peringatan pemakaian logis 80% dan 95% tersedia di aplikasi. Pantau pemakaian penyimpanan dan operasi akun di dashboard Cloudflare serta pemakaian transfer dan fungsi Vercel. Batas aplikasi tidak mengubah ketentuan tagihan akun.

## Pemulihan dan penghapusan sumber

Jika inspeksi menunjukkan ketidakcocokan atau kegagalan transfer, gunakan build kompatibel dengan `EVOLVE_STORAGE_WRITE_MODE=paused` dan `EVOLVE_STORAGE_EXPANDED_QUOTA=1`. Build tersebut tetap membaca file berdasarkan penyedianya dan tidak memberi izin unggah baru. Izin yang terbit sebelumnya tetap dapat berlaku hingga kedaluwarsa. Catat status reservasi dan jangan membersihkan rujukan sampai transfer yang sedang berlangsung direkonsiliasi. Jangan kembali ke versi yang hanya mengenal Blob setelah unggahan R2 aktif.

Salinan Blob yang sudah diverifikasi dipertahankan 14 hari sejak setiap penyalinan. Jika satu rujukan R2 gagal selama masa ini, `npx tsx scripts/r2-migrate.ts restore-read <attachment-id>` memverifikasi salinan Blob dengan checksum sebelum memulihkan rujukan baca. Untuk lampiran yang baru dibuat di R2, gunakan cadangan R2 bila objek hilang. Penghapusan oleh pengguna tetap membersihkan kedua salinan yang diketahui. Setelah seluruh rekonsiliasi dan latihan pemulihan lulus, set `EVOLVE_R2_ROLLBACK_DRILL_VERIFIED=1` dan jalankan `npx tsx scripts/r2-migrate.ts retire 10` per batch. Skrip hanya menghapus Blob yang masa simpannya habis dan memeriksa byte R2 sekali lagi sebelum menghapus sumber.
