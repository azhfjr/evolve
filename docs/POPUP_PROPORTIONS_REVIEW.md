# Popup proportions and interaction audit

17 October 2026. The owner clarified that the disproportionate containers are the popups throughout Evolve. Preserve the green identity, English UI, existing data, permissions and task editor inside the workspace. This revision changes the shared popup system rather than replacing unrelated pages.

## Findings and changes

| Observed issue                                                                                                | Correction and acceptance                                                                                                                                                                                                                                                                                                        |
| ------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Desktop search was 460 × 633 px, forcing results into a narrow column                                         | Search has a 600 px maximum width, a compact scope row when space permits, and a separately bounded result list. At 1440 × 900 the revised panel measured about 600 × 585 px.                                                                                                                                                    |
| Expense actions sat around y=916–987 on a 390 × 740 viewport                                                  | Expense uses a 640 px desktop width, an independent content scroller and fixed actions. On the same phone viewport actions occupy y=658–727, with 12 px outside the shell.                                                                                                                                                       |
| Confirmation content touched the dialog edges and the Activity deletion button had no destructive style       | Shared 20 px desktop / 16 px mobile content insets, separate action rows and the existing red destructive-button treatment. File and Activity previews can scroll by keyboard.                                                                                                                                                   |
| Batch and project dialogs could consume an entire phone viewport; bulk actions were partly clipped            | All dialogs retain an outside gutter and a bounded shell. Project, Expense, bulk and CSV editors scroll their content while retaining header/actions. Bulk fields use a normal scroll container around the fieldset; the browser's special fieldset box otherwise let focused contents scroll the entire shell on short screens. |
| Closing a nested picker by keyboard could leave focus on its parent dialog                                    | Restore the trigger when the parent dialog receives fallback focus; preserve focus when the user has already moved to another actual field.                                                                                                                                                                                      |
| Empty-state, checklist-count and People summary/action text used fixed colors with poor contrast in dark mode | Use semantic text/muted colors; dark task checklist counts previously measured 2.87:1, below 4.5:1. Check dark task lists and Expense/People states.                                                                                                                                                                             |
| Generic dropdown content had no shared height bound                                                           | Limit menus to the viewport / Radix collision space and allow internal scrolling. Existing picker positioning, touch targets and reduced-motion settings remain.                                                                                                                                                                 |

The shared shell bounds short forms, saved views, shortcuts, member editing, connection labels, invitation, task/project discard and file/Activity confirmations. Complex project forms retain their own scroll area. Generic short forms can scroll inside the shell on short screens; this is not a promise that every field is visible simultaneously.

## Verification

`e2e/popup-proportions.spec.ts` exercises search, bulk selection and scrolling, CSV, saved views, project creation surfaces, Expense keyboard selection/save/readback and Activity confirmation/cancel at 1440 × 900, 390 × 740, 320 × 568 and 568 × 320. It asserts shell margins, reachable close controls, visible long-form actions, keyboard focus restoration and selected axe rules. Secondary tests cover member editing, connection labels and shortcuts at desktop/mobile widths. Dark/large-text tests exercise Expense, empty-state contrast and search input scaling at 1440/390 px.

Existing browser suites cover real PostgreSQL writes/readback, membership authorization, uploads/private downloads, file removal confirmation, task/project drafts and discard decisions, CSV/bulk atomicity, Cost per currency, Calendar contracts, archive/undo, search, connection labels and management. The full exact-source CI result and preview are recorded in PR #4. A passing geometry check is not a complete UX or security certification.

The public login and all main pages were audited on the previously released source; this revision retains that layout. Authentication/Calendar consent and device reminders are not impersonated. Safari/Firefox, physical devices and production-account mutations remain outside the executed checks.

## Release and recovery

No migration, permission expansion, new dependency or automatic record deletion is introduced. Production baseline before this revision is source `a00b0f62c136a83f9e86f4a84dc79af405fe1267`, deployment `dpl_GqranGNqtqhU3KaQCEfFmhzURozd`. Preview uses isolated demo data; production deployment requires approval for this revision. The compatible baseline retains draft-file privacy, upload tombstones and per-currency Cost behavior. Returning to it restores the previous popup layout; it cannot recover records an administrator explicitly deletes.
