# Overview, theme continuity and proportional workspace surfaces

21 October 2026. The owner approved the bounded design: six useful Overview visuals, an embedded Connection map, account theme before workspace paint, direct sidebar theme choices, tighter Tasks columns, a complete phone month with selected-day agenda, and proportional Activity/Settings. This candidate is not yet approved for Production. Current Production remains application c35545f with schema 0001–0015.

## Behavior and scope

Overview prioritizes current open work, completed work, overdue tasks and unassigned work, then six visuals: created/completed trend, current status, open priorities, open deadline buckets, team workload and project progress. Historical 7/30/90-day selection applies only to the labelled trend. Current snapshots exclude archives; delivery history retains archived tasks. Money and options are outside these task charts. Reports aggregate across the database, not the paginated workspace task payload. Drilldowns carry matching open/status/priority/owner/deadline scopes; legacy Upcoming still includes today, while new Today and After today are disjoint. Saved views retain these scopes. Project progress includes projects with zero tasks.

The layout adapts actionable analytics patterns from [Linear Insights](https://linear.app/docs/insights) and [ClickUp Dashboards](https://clickup.com/features/dashboards): status/priority distributions, workload/progress visibility, and charts leading to underlying work. Official pages were fetched successfully during this review. This is an adaptation to Evolve's existing data and green identity, not a claim to reproduce those products or their rankings.

Overview Connection is a real Label → Project → Task map using the existing fit, pan/zoom, selection and fullscreen engine. Labels are paginated (24/page) and map results bounded (12/page), with accurate counts and contextual parent projects. Opening an unloaded task uses the authenticated task route; changing label/page or unmounting cancels pending opens. Task/project opening errors remain visible. Existing Connection page and label editing remain available through explicit navigation.

Root rendering reads only the verified session's own theme preference without a shared account cache. A validated enum and parser-blocking head bootstrap resolve the theme before body paint. Anonymous login uses validated local preference/system fallback; denied browser storage is tolerated. Explicit Light/Dark/System choices are visible in the sidebar. Saved account preference wins over stale local cache on first authenticated render. System follows OS changes; explicit choices remain fixed. Saving uses the current profile version, restores theme/cache on failure and synchronizes Settings without discarding unsaved account fields. This does not claim fresh Google consent/token exchange.

Tasks use matching, tighter name/project tracks while preserving long wrapping identities, action access and mobile metadata. Calendar retains its desktop month, Today/previous/next and daily overflow. At phone/tablet widths all seven columns fit; a selected-day agenda exposes every task and date-specific creation. Selected agenda dates remain in workspace state when opening/closing task editors or fetching another month. Calendar Today and initial month use the account timezone; month query and display both use Monday-start weeks, including adjacent-month Sunday. Activity groups filters in one compact card and uses denser rows; Settings fills its content panel with appropriately bounded navigation and natural content height. Large text uses existing scalable tokens.

## Verification ledger

- Baseline captured actual public demo at 1440/390 px. Phone Calendar used a 640 px grid in a 390 px viewport. Settings used a 660 px form within a wider panel. Theme probe found document theme unset until after document completion, then dark at approximately 131 ms; this is one laboratory observation, not a field-performance metric.
- RED/GREEN: new filter schemas, theme bootstrap and analytics unit tests; map presence failed on the released version. An independent review found a delayed old-page map task-open race; browser regressions cover both Overview and the main Connection page. The main-page case failed against the earlier compiled candidate; cancellation now follows the full query scope and item cursor. CI trace review also identified two test synchronization gaps: camera fitting publishes on an animation frame, and scrolling a Radix option can move it before a pointer click. The tests now wait for fitted geometry and verify that the intended option was selected; the original outcome assertions remain intact.
- Local unit/PostgreSQL suite: 160 passed, none skipped. Integration checks compare every deadline bucket/priority/open count with real query results and verify empty-project progress.
- Targeted browser suite: 17 passed, including pre-body theme, authenticated SSR/cache precedence, failed-save rollback, chart data/drills, map pagination, mobile calendar, date creation, long task/project identities and account month-boundary behavior. The profile-draft/theme synchronization test also passed, including saved name/Bio fields, Appearance state and reload.
- Type checking, lint, formatting and production dependency audit passed (0 vulnerabilities). Full browser suite, exact-source CI and protected Preview results are recorded in the PR when complete; do not infer them from this candidate document.

Tests use disposable PostgreSQL/synthetic sessions or isolated browser demo storage. No owner session or organization CRUD is impersonated. Physical devices/Safari/Firefox, screen-reader acceptance, field/load metrics, external alerting and backup recovery are not established by these checks. Selected axe checks do not certify universal accessibility or absence of all bugs.

## Release and recovery

A later CI trace exposed an existing Cost-option focus race: a queued animation-frame callback could steal typing from Cost title into Option name. Option focus now follows the React commit before subsequent interaction, and a controlled-clock regression reproduces the old failure. Validation, units and money calculations are unchanged.

No migration, dependency, IAM or money semantics change is introduced. Production requires separate owner approval of the concrete reviewed Preview. Hold automatic alias assignment, verify the exact immutable deployment/source/digest and health/access/demo paths, promote explicitly and restore the prior setting. Keep compatible large-number/per-option support, Calendar deletion recovery, private draft/file tombstones and all applied migration hashes. The current c35545f production application retains the required money/file guards, but it does not understand the new saved-view open/today/future filters. After saving such views, recover using a build that also understands those filters; prefer fixing forward. Never recover using pre-large-number or pre-private-file code.
