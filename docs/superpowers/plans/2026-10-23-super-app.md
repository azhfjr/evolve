# Evolve super-app integration

The user approved Board Room and requested one immersive website containing Locker Room and Board Room, with unchanged login access, a choice after login, shared design/templates and a full audit. Continue the authorized implementation; no production deployment is included.

## Design and implementation decisions

- Keep the native Next.js modular monolith, existing Better Auth session and invitation rules. `/workspace` becomes the authenticated post-login room chooser; `/app` remains Locker Room and `/board-room` remains Board Room, preserving all deep links.
- Add a shared accessible room switcher to both apps and a global settings page. Room switches from Locker Room respect its existing unsaved-editor leave guard.
- Reuse actual profile/workspace configuration for themes, accent, compact density, reduced motion, branding and navigation. No duplicate preference database or migration.
- Reuse the existing AccountSettings component on a shared route with restricted settings commands. Expose the existing task-template workflow and Board Room CSV/stage workflows through a shared template directory; domain records stay separate.
- Keep the existing approved visual layout. Build the chooser from two purposeful, keyboard-accessible room cards with real aggregate context and small domain-specific previews, using the shared design tokens and responsive styles.

Alternatives rejected: separate domains/logins would break one-session continuity; merging task records into Board Room would change approved workflow semantics. The builder selects the reversible shared-shell approach under the user's request to use imagination and continue building.

## Acceptance and checks

- [x] Google login callback selects `/workspace`; active users can enter both rooms, old URLs still work, outsiders/disabled/guests cannot access hub/settings or data.
- [x] Shared room switcher works with keyboard, mobile drawers and unsaved task edits; sign-out ends access to both rooms.
- [x] Saved personal/workspace design preferences apply to both rooms and hub; shared settings retain optimistic versions, active membership, same-origin checks and role permissions.
- [x] Template directory links/downloads and all room entry/switch actions are real; no placeholder handlers.
- [x] Run full types/lint/tests, production build, relevant existing browser regressions, responsive/a11y browser checks and independent code review. Fix findings and record evidence.
